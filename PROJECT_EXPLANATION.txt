1. PROJECT OVERVIEW
===================

This project is a full-stack TaskVerse.

It is used to manage company-related data such as:

- Users
- Departments
- Employees
- Projects
- Tasks
- Task comments
- Dashboard summaries
- Reports

The project is built with a Django REST API backend and an Angular frontend.

The backend creates APIs. The frontend consumes those APIs and displays screens for users.

In simple words:

- Django backend stores and manages data.
- Django REST Framework exposes APIs.
- Angular frontend displays pages and forms.
- Angular calls backend APIs using HTTP requests.
- JWT authentication is used to protect private APIs.

Purpose:

Important fields:

- phone_number

- created_at

Important point:

Login uses email, not username.

In the User model:

USERNAME_FIELD = 'email'

User roles:

- ADMIN
- MANAGER
- EMPLOYEE

Admin control implementation:

- ADMIN users have full management access.
- Non-admin users can access authenticated read APIs where allowed.
- Non-admin users cannot create, update, delete, assign, or change management records through direct API calls.
- Backend permissions enforce this rule, so users cannot bypass the frontend by calling APIs manually.
- Frontend pages remain accessible to authenticated users for viewing/searching/filtering.
- Admin-only forms, tabs, edit buttons, delete buttons, assign controls, and management actions are hidden for non-admin users.
- Dashboard admin panel is shown only for ADMIN users.

Current management controls protected for ADMIN users:

- Department create/edit/delete controls
- Employee create/edit/delete controls
- Project create/edit/delete/assignment/status controls
- Task create/edit/delete/assignment/status controls

Task comments are collaborative:

- Authenticated users can view and add task comments.
- Task creation, assignment, update, delete, and status management remain ADMIN-only.

Authentication APIs:

POST /api/auth/register/
POST /api/auth/login/
POST /api/auth/logout/
GET  /api/auth/profile/
POST /api/auth/change-password/
POST /api/auth/token/refresh/

- Clicking View comments opens the comments viewer
- Existing comments are displayed with author email and timestamp
- User can add a new comment from the same viewer
- Task list refreshes after adding a comment so comments_count is updated

Overdue meaning:

A task is overdue only when:

 due_date < today
 AND status is not COMPLETED

Examples:

- Due date yesterday + IN_PROGRESS = Overdue
- Due date yesterday + TODO        = Overdue
- Due date yesterday + COMPLETED  = Not overdue because work is complete

Current seeded demo data keeps overdue realistic.
It does not make every department overdue.
Only a small set of open tasks are overdue.

10. JWT AUTHENTICATION FLOW
===========================

This project uses JWT authentication.

Login flow:

1. User enters email and password in Angular login page.
2. Angular calls:

   POST /api/auth/login/

3. Backend verifies credentials.
4. Backend returns:

   - access token
   - refresh token
   - user details

5. Angular stores token.
6. Angular sends token in protected API calls.

Header format:

Authorization: Bearer <access_token>

Protected APIs require this token.

Public APIs:

- Register
- Login
- Token refresh
- Health check
- Swagger docs

Protected APIs:

- Departments
- Employees
- Projects
- Tasks
- Dashboard
- Reports
- Profile
- Change password
- Logout

Role-based control:

- ADMIN can manage Departments, Employees, Projects, and Tasks.
- EMPLOYEE and MANAGER cannot perform management writes through the API.
- EMPLOYEE and MANAGER can open list pages for viewing, searching, and filtering.
- EMPLOYEE and MANAGER do not see admin-only forms, tabs, edit buttons, delete buttons, or management actions.
- Task comments remain available to authenticated users.

12. HOW TO RUN THIS PROJECT ON ANOTHER MACHINE
==============================================

Prerequisites:

Install these first:

1. Python 3.12 or compatible Python 3 version
2. Node.js compatible with Angular 20
3. npm
4. Git, if copying from repository
5. Optional: MySQL, only if using MySQL instead of SQLite

Recommended local setup uses SQLite because it does not require separate database installation.


12.1 Copy or Clone Project
--------------------------

If using Git:

 git clone <repository-url>
 cd "TaskVerse"

If copying manually:

Copy the full project folder to the new machine.

Project folder should contain:

- backend/
- frontend/
- README.md
- PROJECT_EXPLANATION.txt


12.2 Backend Setup on Windows PowerShell
----------------------------------------

Open PowerShell in the project root folder:

 cd "C:\path\to\TaskVerse"

Create virtual environment:

 py -m venv .venv

Activate virtual environment:

 .\.venv\Scripts\Activate.ps1

If activation is blocked, run:

 Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
 .\.venv\Scripts\Activate.ps1

Install backend dependencies:

 python -m pip install --index-url https://pypi.org/simple -r backend\requirements.txt

Go to backend folder:

 cd backend

Run migrations:

 python manage.py migrate

Optional but recommended for local demo/testing:

 python manage.py seed_demo_content

This command restores local demo content, including:

- Departments for Angular, Python, Java, Digital Marketing, Sales, Data Analytics, Engineering, Operations, Human Resources, and existing local departments
- Raman, Yaswanth, and Admin login accounts
- Linked employee profiles for those accounts
- Demo projects covering all departments
- Demo tasks covering project, assignee, status, priority, unassigned, comments, completed, and overdue examples
- Seeded comments for testing the task comments viewer

The command is idempotent, so it can be run again safely if demo data is missing.

Seeded demo data after latest local update:

- Departments: 11
- Employees: 16
- Projects: 17
- Tasks: 44
- Comments: 88
- Open overdue tasks: small realistic subset, not every department

Run backend server:

 python manage.py runserver 127.0.0.1:8000

Backend will run at:

 http://127.0.0.1:8000/

Health check:

 http://127.0.0.1:8000/api/health/

Swagger docs:

 http://127.0.0.1:8000/api/docs/
